# FinRedOps 1.0.0 explicit non-claims

Version 1.0.0 is the first **stable production-reference release** of the FinRedOps governance/control-plane contracts. The version number does not expand testing authority and does not turn deployment assumptions into verified facts.

FinRedOps 1.0.0 does **not** claim to be:

- an autonomous penetration tester or general exploit framework;
- a generic shell/command execution platform;
- authorization to test any target;
- a production-target active-testing engine;
- an autonomous target discovery, crawling, port-scanning, credential-attack or payload-generation system;
- a legal opinion, regulatory acceptance decision, independent audit or compliance certificate;
- proof that a deployment's OIDC, cloud IAM, KMS/HSM, PostgreSQL, firewall, secret store or backup configuration is correct;
- a creator/custodian of institution private keys or KMS credentials;
- physical WORM storage or a media-sanitization product;
- a Byzantine/public transparency log or trusted timestamp authority;
- proof of VM/container/kernel isolation or actual SDN/firewall enforcement for an external worker;
- a guarantee that emergency stop can retroactively undo a network request already sent;
- a guarantee of zero vulnerabilities, high availability, a particular RTO/RPO, or operational staffing quality;
- universal WCAG conformance for downstream user interfaces;
- an external-human penetration-test or security-certification result.

## What v1 does claim

Within the documented reference boundaries and when configured correctly, FinRedOps 1.0.0 provides stable versioned governance contracts for:

- proposal-only AI planning with deterministic deny-by-default policy;
- human approval and cryptographically bound reviewer/business/report/configuration decisions;
- offline pinned OIDC/JWKS identity verification;
- exact-subject tenant authorization and PostgreSQL RLS/service-account verification;
- institution-owned envelope-encryption and signing provider boundaries, including the built-in AWS KMS adapter;
- independently trusted external audit-anchor receipts;
- encrypted evidence lifecycle with custody, retention, legal hold and recovery semantics;
- version-pinned SARIF/CycloneDX/CVSS/ASVS assurance evidence;
- a separately operated, non-production-only isolated-worker execution contract;
- release integrity, checksums, build provenance and supported v0.9.3-to-v1 upgrade guidance.

Every active action remains subject to explicit scope, approval, timing, safety and non-production constraints. v1 stability preserves rather than relaxes those restrictions.
